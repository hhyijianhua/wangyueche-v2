# 多级管理员账号（超管 + 普通管理员）实现计划

## 仓库调研结论

### 现状（单密码锁模型）
- **鉴权模块**：[app.js](file:///c:/Users/Administrator/Desktop/新建文件夹/wangyueche/app.js#L1-L186)
  - `AdminAuth`：单密码模型，存储 `wyc_admin_pwd_v1`（FNV-1a hash）+ `wyc_admin_token_v1`（hash 值即 token，7 天持久化）
    - `tryLogin(pwd)`：单密码比对；`tryChange(old,new,new2)`：只改一个密码
    - `isUnlocked()`：只有两种状态（真/假），**不区分权限等级**
    - `requireWrite(label)`：所有写操作前置校验；`_applyUI()`：只切换红绿框 + 显示"只读/管理员"
  - `AdminUI`：只有两个 Pane（登录/改密码），没有账号输入框、没有管理员列表、没有增删账号按钮
- **HTML 弹窗**：[index.html](file:///c:/Users/Administrator/Desktop/新建文件夹/wangyueche/index.html#L262-L299)
  - 登录 Pane 只有 `adminLoginPwd`（密码输入），无账号
  - 改密 Pane 只有 `adminOldPwd / adminNewPwd / adminNewPwd2`
  - 底部按钮只有 `🔑 改密码 / 🚪 退出登录 / 关闭 / 💾 保存`
- **样式**：[style.css](file:///c:/Users/Administrator/Desktop/新建文件夹/wangyueche/style.css#L1547-L1692)
  - 红绿按钮框/只读提示条/modal 基础样式已具备，但缺乏超管徽章、管理员列表、tab 切换、增删账号行等样式
- **写操作拦截**：AppData 增删改 + Render 的所有 edit/delete/save/renew/uploadImage/deleteImage 全部已挂 `requireWrite` 前置拦截（已验证正确）
- **持久化**：全部在浏览器 localStorage（和车辆数据一致，纯前端、本地浏览器存储）

### 新需求（用户原文）
> 超级管理员账号 15874580880 密码 6 个 1，超级管理员可以添加管理员账号

- 两级权限：
  - **SuperAdmin（超管）**：固定账号 `15874580880` / 初始密码 `111111`；**可改密码**，**不可被删除**
    - 数据级权限：增删改查、上传证件（所有写操作）
    - 管理员级权限：① 新增普通管理员；② 删除普通管理员；③ 重置普通管理员密码
  - **Admin（普通管理员）**：由超管在弹窗内手动创建（账号+密码）
    - 数据级权限：同超管（增删改查+传图）
    - 管理员级权限：① **不允许**新增/删除管理员；② 不能改别人密码；③ 只能改**自己的**密码
- 登录入口改为：**账号 + 密码**双输入框（不再只有密码）
- 旧版本"单密码 123456"兼容：保留作为匿名管理员（或升级为账号 `admin` / 密码 `123456`，避免旧用户首次升级后登不进）

## 依赖顺序的实现步骤

1. **app.js — AdminAuth 升级**（先写最底层，UI 后接）
   - 数据结构：`wyc_accounts_v1 = [{username, pwdHash, role: 'super'|'admin'}]`
   - 固定种子数据：首次加载 localStorage 无账号时，写入
     - `{username:'15874580880', role:'super', pwdHash: hash('111111')}`
     - `{username:'admin', role:'admin', pwdHash: hash('123456')}`（兼容旧版单密码模型，老用户不用重新认识世界）
   - `wyc_current_session_v1 = {username, role, token, expiresAt}`（token = hash(username+pwdHash+timestamp)，7 天）
   - 方法重写：
     - `_seedIfEmpty()`（首次创建种子账号）
     - `getAccounts()` / `_saveAccounts(list)`
     - `findAccount(username)` 返回 `{u,pwdHash,role}` 或 null
     - `tryLogin(username, pwd)`：校验账号+密码 → 写入 session
     - `isUnlocked()`：session 存在且未过期
     - `isSuper()`：session.role === 'super'
     - `currentAccount()`：`{username,role}` / null
     - `lock()`：清 session
     - `tryChangeSelfPwd(old,new,new2)`：普通管理员/超管均可用，只改自己
     - `superCreateAccount(username, tempPwd, role='admin')`：前置 `requireSuper`；账号长度 2-32，密码至少 4 位；**账号名大小写不敏感（trim + 小写比较）**，防止大小写重名；禁止创建 `15874580880` 这种保留名
     - `superDeleteAccount(username)`：前置 `requireSuper`；**禁止删当前账号 + 禁止删唯一超管账号**（两个兜底条件）
     - `superResetPassword(username, newPwd)`：前置 `requireSuper`；重置普通管理员密码（超管自己的密码只能走"改自己的密码"）
     - `requireWrite(label)`：等价 isUnlocked()，兼容现有所有调用点（**零修改现有 20+ 处调用**）
     - `requireSuper(label)`：超管专属操作的二次防御（给管理员列表按钮点击 + AdminUI 内部增删调用）
     - `_applyUI()`：`body.admin-readonly` 仍照旧；额外显示角色（🔓 超管 / 🔓 管理员）；`adminBtn` 超管加 `admin-super` class（金色描边）
2. **app.js — AdminUI 重写**（接底层）
   - 模式（`this.mode`）从 `login/change` 扩展为：`login`（账号+密码）/ `profile`（改自己的密码）/ `manage`（管理员列表，超管才允许）
   - Tab 按钮：`登录解锁 / 我的资料 / 👥 管理员列表`（第三项 `isSuper()` 才显示，否则隐藏）
   - 提交按钮 `_submit` 按当前 tab 分派：
     - `login` → `AdminAuth.tryLogin(u,p)`
     - `profile` → `AdminAuth.tryChangeSelfPwd(old,new,new2)`（**永远只能改自己的**，和角色无关，避免超管误入改别人的）
     - `manage` 下每个账号行的「删除」「重置密码」「新建」单独按钮，不走 _submit（行级事件）
   - `_renderAdminList()`：超管管理 tab 下渲染 `<table>` 或卡片，列名 = 账号 / 角色（超管徽章/普通管理员） / 创建时间（可选，简化不计） / 操作
     - 超管账号 `15874580880`：操作列只显示「重置密码为 123456？」不显示「删除」（保护）
     - 普通管理员：操作列显示「重置密码」+「删除」
     - 管理 tab 底部放「➕ 新建管理员」行（账号 + 初始密码 + 角色下拉（暂时只能选 admin，防自己把自己降级）） + 「保存」按钮
   - 登录 Pane 账号输入框：`type="text"`，placeholder `账号（15874580880 或 admin）`
   - 登录失败区分消息："账号不存在" / "账号或密码错误"（简单起见不区分，统一为「账号或密码错误」，避免枚举账号攻击虽然前端其实没啥防的必要，但习惯保留）
3. **index.html — adminModal HTML 扩展**
   - `adminLoginPane`：在密码行上方加账号行（`adminLoginUser` 账号输入框）
   - 新增 `adminProfilePane`：改自己的密码（三输入：旧密码/新密码/确认，和原 changePane 内容一样，id 全改成 `meOldPwd / meNewPwd / meNewPwd2`）
   - 新增 `adminManagePane`：
     - 标题 "👥 管理员列表（仅超级管理员可见）"
     - `<div id="adminListTable">` 放渲染出来的表格（JS 动态渲染，HTML 只留容器）
     - `<div id="adminCreateRow">`：新建账号的 3 个控件（账号输入框 `newAdminUser` / 密码 `newAdminPwd` / 保存按钮） — HTML 静态写好也可以，渲染也行，这里静态写好
     - 底部给一行 hint："💡 只有超级管理员 15874580880 才能看到此页"
   - 底部按钮组改：

4. **style.css — 视觉微调**

## 依赖和注意点
- **向后兼容**：现有 20+ 处 `requireWrite(label)` 调用点零修改；`isUnlocked()` 对"普通管理员 + 超管登录"都返回 true，旧 UI 逻辑不变
- **超管不可删除 / 不可被重置密码（只能改自己的）**：两个兜底 if 判断，防止误操作把自己锁死
- **账号名大小写 + 空格**：统一 `u.trim().toLowerCase()` 存，比对也走同规则，防止"Admin / admin"两个账号
- **浏览器刷新仍登录**：session 有 `expiresAt = now + 7天`，刷新读 `wyc_current_session_v1` 自动恢复（同旧 token 机制）
- **云同步账号？** 这次**不做云端账号表同步**（避免越权、前端本来就没法安全存超管密码；且用户场景明确是"同公司几个管理员共用本地/同一套 Supabase 数据"，但账号管理纯浏览器本地足够 — 需要的话以后可再升级为 admin_users 云表 + RLS 只允许 super 增删）；如用户后续有"每台设备登录账号密码要一致"的诉求再做

## 风险与处理
- **风险 1：升级后老用户登不进**（因为之前只存了 `wyc_admin_pwd_v1` hash，不知道明文，没法自动迁移成具体账号）→ 处理：默认种 `admin / 123456` 兼容账号，老用户首次用账号 `admin` 密码 `123456` 登录即可（和之前单密码体验高度相似，只是多输个账号 admin）；文案在 placeholder 和 hint 写清楚
- **风险 2：超管改完自己密码忘了，彻底锁死** → 处理：提供「紧急重置」说明（超管密码忘了的话，在浏览器 Console 执行 `localStorage.removeItem('wyc_accounts_v1'); localStorage.removeItem('wyc_current_session_v1'); location.reload();` 清空账号回到种子状态，超管又变回 `15874580880 / 111111`）；在 hint 里只写"请牢记密码"，不写怎么 Console 重置，怕被普通人乱点；只在这文档里留给你本人知道
- **风险 3：`role: 'super'` 字符串写错或误存** → 处理：`findAccount()` 返回时统一 `role = (role==='super')?'super':'admin'`，做一次清洗
